# 履歴の進捗更新(AgentCore版)

taskmanagerの履歴(TaskHistory)のうち、日付・分類・担当者・ステータスが未入力の
レコードについて、content(内容)欄のテキストから内容を解釈し、それぞれの項目を
判定して更新するスキル。CSVで一括登録された履歴は日付等が空のまま取り込まれるため、
このスキルで後から埋める運用を想定している。

このスキルは `mcp__task-manager__list_history` / `mcp__task-manager__update_history_entry`
(taskmanagerのTaskHistoryテーブルを直接読み書きするMCPツール)のみを使う。
Google Driveやレシート処理には関与しない。

## Step 0. 関与先の確認

プロンプトに関与先コードが含まれていなければ、`mcp__task-manager__list_clients` で
候補を取得し、ユーザーにどの関与先(案件)を処理するか確認する。

## Step 1. 履歴レコードの取得

```
mcp__task-manager__list_history(client_code="{関与先コード}")
```

返るレコードは `historyId, date, category, assignee, status, content, createdAt, updatedAt`
を持つ。

## Step 2. 更新対象の絞り込み

`date` / `category` / `assignee` / `status` のうち空文字(未設定)の項目だけを更新対象とする。すでに値が入っている項目手で入力・確認済みとみなし**上書きしない**(再実行しても安全なように、この判定を必ず行う)。

対象が0件なら「更新対象の履歴はありません」と報告して終了する。

## Step 3. 内容の解釈

対象レコードそれぞれについて、`content` の文面から以下を判定する。

- **日付**: 「8/1」「2026-08-01」「8月1日」のような日付らしい記述があれば
  `YYYY-MM-DD` 形式に変換する。年の記載が無ければ `createdAt` の年を使う。
  読み取れない場合は空文字のままにする。
- **分類**: データの種別を表す短い言葉(例:「ｘｘ銀行」「売上」「給与」「請求書」「支払」）
  既存の分類から推定できるものがあれば、それを充てる。
- **担当者**: content中の人名らしき文字列(敬称付き含む)。複数候補がある場合は
  依頼者ではなく実際に対応した人物を優先する。読み取れなければ空文字のままにする。
- **ステータス**: 必ず次の6つのいずれか一つに分類する
  (これ以外の値を入れてはいけない。空文字も不可):
  - `未着手` : まだ何も着手していない・予定のみ
  - `依頼中` : 先方や担当者に依頼した段階
  - `確認中` : 内容の確認待ち・返答待ち
  - `進行中` : 着手済みだが完了していない
  - `完了` : 「完了」「済」「送付済み」など完了を示す記述がある
  - `NA` : 進捗管理の対象外(雑談・単なるメモなど、上記どれにも当てはまらない)

## Step 4. 更新の反映

判定した4項目を1レコードずつ反映する。

```
mcp__task-manager__update_history_entry(
    client_code="{関与先コード}",
    history_id="{historyId}",
    date="{判定した日付 or 空文字}",
    category="{判定した分類 or 空文字}",
    assignee="{判定した担当者 or 空文字}",
    status="{必ず6値のいずれか}",
)
```

## Step 5. 報告

更新した件数と、担当者や分類の判定に自信が持てなかったレコード(空文字のまま残した
項目があるもの)を簡潔に報告する。

## 補足

- 既に何らかの項目が入力されている履歴は上書きしない(Step 2参照)。これにより
  何度再実行しても、未入力のレコードだけが対象になる。
- ステータスだけは判定に自信が持てなくても必ず6値のいずれかを選ぶこと
  (空のままだと画面(StatusSelect)のプルダウン表示が崩れるため)。
- 1件のcontentに複数の話題が混在していても、レコードを分割・統合したりはせず、
  1件のまま最も主要な情報を反映する。
- 関与先ごとに履歴は完全に独立している。複数の関与先をまとめて処理してほしいと
  言われた場合は、関与先ごとにStep 0〜5を繰り返す。
